## 1. BCF5D17A 消费链（FUN_01AE6420）

逐语句/基本块分析：
1. 从 item view +0x10 读取 row；空 row 或首 u32=0 返回 0。
2. PTR_DAT_04BBFE88 是初始化标志，首次设置 1 并将 PTR_DAT_04BBFE90 指向的 0x1AC 字节清为 FF。
3. cache+0x10C 是 signed field offset；>=0 时用 row+offset 读 u16；0xFFFFFFFF 表示尚未解析，其他负数失败。缺字段扫描前写入 0xFFFFFFFE。
4. 由 row 的回溯偏移取得 BCSV header，按 header+0xA flag 选择 0xC/0x1C，逐 8B 字段描述符比较 0xBCF5D17A（反编译 signed -0x430a2e86）。命中 offset -1 时写 0，否则保存 offset。不能把这一缓存当作玩家存档。
5. u16 index <0x800 时，读 PTR_DAT_04BB46F0 所指对象的 +0xE98E0+(index>>3) 并提取 index&7；否则返回 0。该 bitmap 可寻址 0x100 字节，写入者和业务名仍未知。

```cpp
// 省略字段缓存解析与所有无效 header 路径。
bool BitmapPredicate(View v) {
  if (!valid_row(v.row)) return false;
  auto field = ResolveCachedFieldOffset(0xBCF5D17A);
  if (!field.valid) return false;
  uint16_t n = ReadU16(v.row + field.offset);
  if (n >= 0x800) return false;
  return (bitmap[n >> 3] >> (n & 7)) & 1;
}
```

00EFA550 在普通谓词为真且 Native Kind==0 的分支将该结果 XOR 1 后返回。这个取反只证明特定调用者的行为，不是全局赠礼许可。

## 2. 两套风格的读取差异

- 01AE0CF0：与上面的 BCSV 字段缓存共用初始化标志和缓存对象，偏移槽 +0x8C，查 9BA040C2，按 u32 读；<7 有效。
- 01AE0C40：不扫描风格字段，而是从 row 回溯到 header、按 header flag 算数据起点、用 stride 将 row 转成 index；在 DAT_05326C78 count 范围内，从 DAT_05326C80 读 u16。两套 getter 的 null row 均返回 1，其他无效路径返回 0。不能把 0/1 当成两套风格的业务命名。
- 01A77904 的 STRH 是历史定位的 writer；必须追其前驱和两套七项字符串表才能建立第二风格原始字段关系。

## 3. 包装分派与记录归一化

01B03610 依次比较全局 0532A75C/60/64 与参数，返回 1/2/3，未匹配返回 0；三个全局实际值仍未知。01B079EC 并非返回一个物品 ID，而是通过 output 指针写出 8B item record。

01B079EC 主要阶段：
- 两个静态初始化 guard 0532ACF0/0532AD00 对应默认记录 0532ACE8/0532ACF8，低字分别初始化为 0x9C4/0x839，并调用 0277D4AC。
- 复制 view+8/+0xC 两个 u32 构造临时对象（VTable 04A36B50）；通过 0277D6C4 取 catalog ID，用 catalog manager+0x57E58、table+0x1F8 base ID、+0x1D8 count、+0x1E0 pointer array 验证。
- 多次调用 01B032D0，按条件处理 item header 中的 0x3000000、0x40000000 及 byte3 位域；真实位域名未确认。
- 读取原始 view+0xB 的低 2 bits 和 bits[5:2]；类型值 3 且后一字段不等于 0xF 时进入 01B03610 映射路径。
- 特殊分支比较 Native Kind 0x86/0xB4/0xB3/0xB2/0xB9；Kind 表 05326EC0/05326EC8 的边界为 <0xBD，必须关联原始 enum 才能命名。
- 终点可能输出原 8B、临时规范化记录或上述两个默认记录。01AF2868 参与原始/规范化选择；仍需 ABI 及 CFG 证明所有分支。

## 4. 两个候选谓词的结构差异

01B07660 / 01B081A0 共有前置 01AFCFA0、01AFD600、01B085E0 与实例检查 01B032D0。若 flag mask 0x18==0x10（在相应上下文条件成立时）或 01B085E0 为假，两者拒绝。包装状态非零时，前者调用 01B079EC、重建临时 view 后递归自身；后者额外检查 Kind 0xB9，非该值才走归一化递归。

## 5. 00EFA550 额外谓词

该函数先经 05327180/88 行索引表值 1 直接拒绝；另一个表 PTR_DAT_04BC0050 的值 2 进入两项额外检查 01B160F0 / 01B164E0。之后调用 01B07660；真值时按 Native Kind 分流：
- Kind 0x60..0x70 内，mask 0x10601 命中（0x60/0x69/0x6A/0x70）直接接受。
- Kind 9/10，比较另一行表 053271B0/B8 值与 *param_2（值 0 或相等），同时 01AE58B0 与 *param_3 比较（0 或相等）。
- Kind 0，返回 01AE6420 XOR 1。
- 其他返回 0。
两个外部参数来源未知；不能把它们擅自命名为玩家、村民性格、风格或颜色。
