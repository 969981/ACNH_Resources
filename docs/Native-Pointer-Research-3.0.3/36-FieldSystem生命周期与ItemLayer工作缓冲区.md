## 3. ItemLayerWorkHeap与真实网格（C）

[012E4640](../../derived/3.0.3/ghidra12.2/c/46/012e4640.c) blob 98087e2a26822119efdfcc249b4b8363d5cf4412：按描述符标志选择是否创建辅助对象、位图、工作堆。原版字符串ItemLayerWorkHeap明确用于独立工作堆分配；以虚函数取得网格宽高，并为工作缓冲区分配每格8字节记录、初始化默认空记录。工作缓冲区存在不代表实际持久化数据在此处。

[012E4B00](../../derived/3.0.3/ghidra12.2/c/4b/012e4b00.c) blob 8881f37b447f193c6d4b2502e7f34d5c51704ac6：先校验输出描述符与真实网格宽高，随后通过网格后端取得源数据，复制至独立的目标缓冲区，复制坐标原点并按位图处理部分记录。这里有直接的网格→工作快照 C证据；不是反向写回证据。

## 4. 研究边界及本轮提交

实际原版存在通用网格数据、工作快照和独立保存管理器三类层次。当前还不能证明FieldSystem网格后端与Mode3保存区域是同一内存对象或通过复制同步。后续以正常游戏操作的只读观察、离线自有存档对比以及保存前后数据一致性验证，不将缓存当作持久化依据。
