# 10 · 字段证据等级与已知旧映射错误

## 证据状态
| 等级 | 含义 | 是否能生成确认值 |
|---|---|---|
| 原始 ROM SHA + 指定字节偏移 + 实际类型 | 可与原始文件逐字节验证 | 可以 |
| CRC32 名称/类型与 3.0.3 原始哈希匹配 | 字段名与签名匹配，值依旧要分辨枚举或单位 | 只能直接转换原始数字/字符串，不能臆测作用 |
| R77/R82/R84 已采集的身份关系 | 有脚本及实测样本，但可能存在特殊情况 | 用 evidence 保存 |
| 历史 1.6.0 文档推断/版本参考 | 历史语义或默认值，不保证 3.0.3 完全一致 | 候选 |
| 旧网站文本和列表推断 | 网站衍生行为、翻译后缀、展示排序 | 原样另存，不能回写成 Nintendo 原版 |

## 2026-11-14 发现的两处关联错误

### 1. RecipeCraftParam 的成品和材料混用
- **正确**：`hash_89A3482C` = `CRC32("Item u16")`，是配方最终产物 Item ID。
- **正确**：`hash_1BBFA75E` = `CRC32("Material1 u16")`，是第一种材料 ID。
- 旧文档有把后者写成“产物候选字段”的说法，应停止使用。示例 recipe 6：Item 2596、Material1 2213、Material2 2511。

### 2. ItemRemake 自身 ID 和物品外键混用
- **正确**：`hash_54706054` = `CRC32("UniqueID u16")`，是改造记录主键。
- **正确**：`hash_FD9AF1E1` = `CRC32("ItemUniqueID u16")`，是指向 ItemParam 的物品 ID。
- 原先 `Scripts/acnh303_r84_native_item_database.py` 使用 `hash_54706054` 关联 ItemParam，使 **821 个所谓精确关联项的数值不可信**。修复源代码后须重跑原版 CSV/SQLite 输出及报告，不能复用旧的 821 结论。

## 其他限制
- 旧 `villager_db_multi.nameEn` 的英语地区：**EUen**，不是 USen。
- `ItemKind.MultiHoldMaxNum s16=-1` 是特殊值，不能显示为 65535 件。
- R80 服装组前缀匹配，R84 文件存在性、原版 UI 动态选图，各有不同证据等级。
- 11,178 原版物品与旧站 10,789 非 DIY 物品的差额 389 已完成集合差；但旧站完整过滤逻辑未确定。
- 924 配方材料、17,170 变体的全量逐项重建，需要新的原生对账与运行时证据。
