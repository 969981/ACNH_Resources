# 05 · Windows 上如何复现

## 1. 使用本专题审计脚本（Python 3.10+，标准库）
将本轮离线研究包的旧 JSON 和两份完整原生导出 CSV 放到各自路径；仓库中的大型原版文件并不能直接当成该脚本所需的四个同名输入。以下在仓库根目录的 PowerShell 运行：

~~~powershell
py -3 docs/ACNH303_JSON_Rebuild/Scripts/audit_acnh303_json.py `
  --items 'D:\ACNH_Audit\web_db_multi(1).json' `
  --villagers 'D:\ACNH_Audit\villager_db_multi(1).json' `
  --native-items 'D:\ACNH_Audit\ACNH_3.0.3_Items.csv' `
  --native-villagers 'D:\ACNH_Audit\ACNH_3.0.3_Villagers.csv' `
  --repo-root . `
  --out 'D:\ACNH_Audit\reports'
~~~

脚本只读输入。若 repo-root 中有 UnPack/1/Bcsv/RecipeCraftParam.csv 与 ItemRemake.csv，可额外检查原版配方集合和候选产物关系。

## 2. 原版 RomFS 重新解包
~~~powershell
git switch 3.0.3_Unpack
py -m pip install -r Scripts/requirements.txt
py -m pip install zstandard
py Scripts/mirror_unpack.py basic --file Bcsv/NmlNpcParam.bcsv
py Scripts/mirror_unpack.py basic --file Bcsv/ItemParam.bcsv
py Scripts/mirror_unpack.py basic --file Bcsv/ItemKind.bcsv
py Scripts/mirror_unpack.py basic --file Bcsv/RecipeCraftParam.bcsv
py Scripts/mirror_unpack.py basic --file Bcsv/ItemRemake.bcsv
py Scripts/mirror_unpack.py audit
py Scripts/acnh303_r76_msbt_probe.py
py Scripts/acnh303_r78_query_catalog.py stats
~~~

R77→R80→R81→R82/R84 的原生 SQLite 构建可按仓库相应脚本复现，不应拿现成 CSV 的对账冒充原生二进制重建。仓库提供 r82-acnh303-villager-provenance.sqlite3.zst 与 r80-acnh303-multilingual-clothing-enriched.sqlite3.zst；读取时应在临时目录解压、只读连接。R84 目录已有 107 字段和 ID-Remake 关系 CSV；核实时尚未见 R84 SQLite 被直接托管，需本机重新生成。

## 3. 验收必须满足
- 原版 ItemParam=11,178、普通 NPC=417、RecipeCraftParam=924
- 旧非 DIY=10,789，均有同 Item ID/ResName，原版额外 389
- 旧村民 nameEn 与 EUen=417/417；USen 有两个地区差异
- 旧 DIY 924 个 recipe_id 唯一；全部共用旧商品 id=5794
- 旧站 variations=17,170，解码错误 0
- 不将未知价格字段、ItemKind 特殊堆叠值或 UI 动作提升为已验证语义
