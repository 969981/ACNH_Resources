# 11 · 道具分类和可操作标志：已经验证到哪一级？

原版 `UnPack/1/Bcsv/ItemParam.csv` 共 **11,178** 个 Item ID，细分类为 `hash_FC275E86`（例 `Kind_Fruit`）；`ItemKind.csv` 有 **189** 个 Label（`hash_87BF00E8`）、操作标志（`CanPut/CanSell/CanPlant/CanSetChest` 等）、持有堆叠规则（`hash_4C9BA961`，有符号 s16）。

| 物品级类别关联 | 物品数 | 可否使用类别标志 |
|---|---:|---|
| 完全同名：`Kind_X` → `ItemKind.Label=X` | **6,076** | 可关联原版类别的**静态规则** |
| 父级前缀候选：`Ftr_`、`Top_` 等 | **5,050** | 只能标记候选，不把标志当原版确定值 |
| 未匹配，例如 `UnitIcon_Flw*` | **52** | 保留未知，不自行分类 |

## 从哪个文件读取？

`[[ACNH303_JSON_Rebuild/fields/ItemParam|ItemParam 全字段]]`、`[[ACNH303_JSON_Rebuild/fields/ItemKind|ItemKind 全字段]]` 和只读脚本 `Scripts/acnh303_r85_item_npc_static_audit.py`。本轮已经按源 `ItemKind.csv` 导出全部 **189 个类别及 18 个标志字段**：

- [原始类别/日文备注/静态标志 CSV](../evidence/r85/itemkind_categories_189.csv)
- [机器可读对账摘要](../evidence/r85/item_npc_static_summary.json)

**例子：** `Ftr` 原生备注 `家具`，`CookingMaterial` 原生备注 `料理：食材`；`Fruit`、`Ore` 具有各自原生规则，但不应把 `s16=-1` 解释为 65,535 件。

## “中文类别”需要多一层验证

`ItemKind.csv.hash_036E8EBE` 中可以直接看到**原生日文注释**（如 `家具`、`料理：食材`），但不是简中 `CNzh` 翻译。语言资源 `Message/String_CNzh.sarc.zs` 的 `STR_CategoryName.msbt` 确实存在，但它的标签未证实与全部 189 个 `ItemKind.Label` 一一对应。不可直接把注释翻译后宣称是 ROM 中文类别。

## 推荐最终导出字段

`item_id, res_name, kind_raw, base_kind, base_kind_evidence, stack_s16, stack_evidence, can_sell_static, can_plant_static, can_set_chest_static, category_cn_name, category_cn_evidence`。

只让 `exact_ItemKind_label` 的原生旗标进入“静态规则已确认”；`category_cn_evidence` 为空则中文名仍未知。实际捡起、购买、存档、联机带走还要 Native trace，不能从类别标志直接推断。

命令：
~~~powershell
py Scripts/acnh303_r85_item_npc_static_audit.py --repo-root . --out r85-output
~~~
输出包含原版 **11,178 条物品类别逐项关联 CSV** 和 **189 类原版规则 CSV**，不自动修改当前游戏存档。
